# Frontline Studio

Редактор линии фронта на карте: наступления с анимацией, серая зона, история и хроника событий,
фронт по странам и провинциям, а также территории поселений, военные базы, аэродромы и высоты
в провинциях фронта.

Всё приложение — один файл `index.html`. Данные о поселениях и базах лежат в папке `data/`
и собираются из OpenStreetMap автоматически.

## Как выложить на GitHub

1. Создайте на GitHub новый **публичный** репозиторий с именем `frontline-studio`, без README.
2. Загрузите в него **всё содержимое этой папки**, кроме `node_modules`, если она есть:
   - через сайт: «Add file → Upload files», перетащите файлы и папки `data`, `scripts`, `.github`;
   - или через GitHub Desktop / git:
     ```
     git init
     git add .
     git commit -m "Frontline Studio"
     git branch -M main
     git remote add origin https://github.com/ВАШ-ЛОГИН/frontline-studio.git
     git push -u origin main
     ```
   Проверьте, что в репозитории появилась папка `.github/workflows`. Если при загрузке через сайт её нет,
   создайте файл вручную: «Add file → Create new file», имя `.github/workflows/update-data.yml`,
   и вставьте содержимое одноимённого файла из этой папки.
3. Разрешите автообновлению данных сохранять изменения:
   **Settings → Actions → General → Workflow permissions → Read and write permissions → Save**.
4. Включите сайт: **Settings → Pages → Source: Deploy from a branch → Branch: `main`, папка `/ (root)` → Save**.
   Через 1–2 минуты приложение откроется по адресу `https://ВАШ-ЛОГИН.github.io/frontline-studio/`.

На GitHub Pages приложение само находит данные. Если открываете `index.html` с компьютера,
укажите в приложении **🎯 Цели → Источник данных** ваш репозиторий `ВАШ-ЛОГИН/frontline-studio`
(данные возьмутся через CDN jsDelivr).

## Как добавить провинции

Данные собираются только для провинций из файла `regions.json`:

```json
{
  "regions": [
    { "id": 1375620, "name": "Северный округ (Израиль)" },
    { "id": 318236, "name": "Южный Ливан" },
    { "id": 318309, "name": "Эн-Набатия" }
  ]
}
```

`id` — номер relation в OpenStreetMap. Проще всего получить его в приложении:
постройте фронт через **🌍 Страны** (или добавьте провинцию в **🎯 Цели → Провинции фронта**)
и нажмите **📋 Скопировать ID для regions.json**.

После изменения `regions.json` на GitHub запускается Action **«Обновить данные OSM»**
(вкладка Actions). Сборка одной провинции занимает от 1 до 5 минут.
Кроме того, данные сами обновляются раз в неделю.

> jsDelivr кэширует файлы до 12 часов. На GitHub Pages новые данные видны сразу после деплоя.

## Что собирается

Для каждой провинции (`scripts/build-data.mjs`):

| Слой | Источник в OSM |
|---|---|
| 🏘 Поселения | контуры `place=city/town/village/hamlet` и муниципальные границы (`admin_level` 8–9). Региональные советы, которые объединяют несколько посёлков, отбрасываются |
| ┄ Примерные территории | для деревень, у которых в OSM есть только точка: зона ближайшего поселения (диаграмма Вороного) в пределах провинции, радиусом до 2.5 км |
| 🪖 Военные объекты | `landuse=military`, `military=*` |
| ✈️ Аэродромы | `aeroway=aerodrome` |
| ⛰️ Высоты | `natural=peak` с названием, до 80 самых высоких |

Контуры упрощаются примерно до 4 м, координаты округляются до 1 м.

Собрать локально (нужен Node.js 20+):

```
npm install
npm run build-data            # все провинции
node scripts/build-data.mjs 318236   # только одна
```
