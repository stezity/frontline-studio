# Frontline Studio

Браузерный редактор карт линии фронта. Территории сторон рисуются прямо на карте
(Leaflet + векторные подложки OpenFreeMap через MapLibre GL), наступления анимируются вместе с серой зоной,
каждое изменение попадает в историю и хронику событий, а всю историю фронта можно проиграть на таймлайне
и записать в видео. Поверх карты показываются реальные контуры поселений, военных баз, аэродромов и высоты
из OpenStreetMap для провинций фронта.

## Открыть

**https://stezity.github.io/frontline-studio/**

Ничего устанавливать не нужно, регистрации нет. Проект сохраняется автоматически в браузере (IndexedDB,
при её недоступности — localStorage) вместе с последними 15 шагами отмены. Чтобы перенести проект на другое
устройство или сделать копию, используйте **⚙ Настройки → Экспорт проекта / Импорт проекта** (JSON).

Для работы нужен интернет: библиотеки, подложки карты, поиск мест (Nominatim) и данные OSM загружаются из сети.

Всё приложение — один файл `index.html`, его можно открыть и с диска. Тогда укажите в
**🎯 Цели → Источник данных** репозиторий `stezity/frontline-studio` (или свой форк) — данные возьмутся через
jsDelivr / raw.githubusercontent.com. На GitHub Pages источник определяется сам.

## Возможности

**Рисование**
- Инструменты: **Обзор** (1), **Наступление** (2) — зажать и свободно обвести территорию (лассо),
  **Кисть** (3), **Рулетка** (4), **Фронт** (5) — начальная территория стороны 1, **Перо** (6) — многоугольное
  лассо по точкам (замкнуть — клик по первой точке, двойной клик или Enter; Backspace — убрать точку,
  Shift — углы по 45°; между кликами карту можно двигать, что удобно на сенсорном экране).
- Серая зона вдоль линии фронта и анимация наступления; ширина серой зоны, длительность анимации и размер
  кисти — в **🎚 Параметры**.
- **⏯ Ход**: действия (лассо, перо, кисть), в том числе за разные стороны, не применяются сразу, а копятся
  и выполняются вместе по **▶ Выполнить ход** (Enter) — одна общая анимация, одно состояние таймлайна,
  один шаг отмены и отдельная новость на каждое действие.
- **↶ Отменить / ↷ Вернуть** (Ctrl+Z / Ctrl+Y или Ctrl+Shift+Z), до 80 шагов; на вкладке
  **🕓 История → Действия** можно вернуться к любому шагу.
- Точное редактирование: вершины фронта, сглаживание, независимая исходная линия; маркеры, подписи, области.
- Стороны: переименование (**✎ Имя** или двойной клик по стороне), цвета, дополнительные стороны,
  грамматический род названия для текста новостей.
- **🌍 Страны** — фронт по границам стран, провинций, областей или округов из OSM: для каждой стороны можно
  выбрать несколько регионов, они объединятся, а их общая граница станет линией фронта.

**История и анализ**
- Таймлайн с воспроизведением (0.5×–4×), **🕓 История** (Хроника, Действия, Снимки), **📰 Журнал** событий,
  сценарное время.
- **📊 Аналитика**: сравнение двух состояний, изменения за период, статистика площади,
  «Частота смены контроля», «История точки».

**🎯 Цели** — объекты OpenStreetMap в провинциях фронта
- Слои: 🏘 поселения (настоящие контуры территорий; поселения без контура и лагеря — точками, районы — пунктиром), 🪖 военные базы и зоны, ✈️ аэродромы, ⛰️ высоты,
  🗺 границы провинций. Цвет объекта — сторона, которая его контролирует; есть сводка «Кто что контролирует»,
  поиск объектов, а занятые объекты упоминаются в новостях события.
- Кроме провинций фронта, при включённом «Показывать на карте» автоматически подгружаются провинции,
  видимые на карте (с масштаба 8).
- Если провинции нет ни в репозитории, ни в кэше браузера, приложение собирает её прямо в браузере из OSM
  (граница — Nominatim, объекты — Overpass API) тем же кодом, что и GitHub Action, и сохраняет в IndexedDB.
  Ход сборки виден в журнале под строкой провинции (кнопка **≡**), **↻** — собрать заново.
- **📋 Скопировать ID для regions.json** — строки провинций фронта для файла `regions.json`.

**Карта**
- Подложки: OpenFreeMap Positron, тёмная OpenFreeMap Dark, OpenFreeMap Liberty, OpenStreetMap HOT,
  спутник Esri; слой «Дороги поверх территории». На тёмной подложке подписи объектов светлые.
- Своё изображение (PNG/JPG/WebP) как подложка или полупрозрачное наложение поверх карты; поиск мест.

**Проекты и экспорт**
- Несколько проектов (**＋ Новый проект** — название, стороны, цвет), дублирование, закладки вида,
  резервные копии, режим просмотра, блокировка редактирования.
- Экспорт и импорт проекта (JSON) и GeoJSON, экспорт истории в CSV.
- **🎬 Экспорт видео**: запись воспроизведения истории прямо с вкладки (Screen Capture API + MediaRecorder) —
  с подложкой, дорогами и объектами, заголовком, датой, новостями и площадью сторон; 30 или 60 кадров/с;
  MP4 или WebM в зависимости от браузера. Работает в Chrome и Edge на компьютере.

**Телефон** — на узких экранах (до 760 px) инструменты в панели снизу, меню **☰** и панели открываются
снизу как выдвижные листы.

## Данные (API)

Данные по провинциям лежат в репозитории в папке `data/` и раздаются GitHub Pages как статические JSON:

| URL | Что внутри |
|---|---|
| `https://stezity.github.io/frontline-studio/data/index.json` | список собранных провинций |
| `https://stezity.github.io/frontline-studio/data/regions/<id>.json` | данные одной провинции, `<id>` — номер relation в OSM |

Те же файлы приложение берёт и с `https://cdn.jsdelivr.net/gh/stezity/frontline-studio@main/data/`
и `https://raw.githubusercontent.com/stezity/frontline-studio/main/data/` (jsDelivr кэширует файлы,
поэтому обновления там появляются с задержкой).

**`index.json`**

```json
{
  "regions": [
    {
      "id": 318236,
      "name": "провинция Южный Ливан",
      "file": "regions/318236.json",
      "bbox": [35.1036, 33.0854, 35.6382, 33.592],
      "counts": { "military": 25, "airfield": 1, "settlement": 229, "peak": 10, "approx": 12, "builtup": 214, "ruins": 0 },
      "updated": "2026-10-02T04:35:11.398Z"
    }
  ],
  "updated": "2026-10-02T04:52:14.901Z"
}
```

`name` берётся из OSM (`name:ru` → `name:en` → `name`), `bbox` — `[запад, юг, восток, север]`,
`updated` — время последнего изменения данных. У провинций, собранных на дату, есть поле `snapshot`
(см. «Сектор Газа»).

**`regions/<id>.json`** — те же `id`, `name`, `updated`, `snapshot?`, `bbox`, `counts`, плюс
`boundary` (упрощённая граница провинции, GeoJSON-геометрия) и `features` — массив объектов:

| Поле | Значение |
|---|---|
| `k` | тип: `settlement` (поселение), `military` (военный объект), `airfield` (аэродром), `peak` (высота) |
| `n` | название: `name:ru` → `name:en` → `name` |
| `q` | варианты названия для поиска в нижнем регистре через `\|` (`name:ru`, `name:en`, `name`, `name:he`, `name:ar`, `int_name`, `alt_name`) |
| `s` | подтип по-русски: «Город», «Посёлок», «Деревня», «Муниципалитет», «Район», «Лагерь беженцев», «Разрушенный населённый пункт», «Военная база», «Полигон», «Военная территория» и т. п., «Аэродром», «Военный аэродром», «Высота», «Вулкан» |
| `p` | точка `[lon, lat]` внутри объекта (у точечных — сама точка) |
| `g` | контур, GeoJSON `MultiPolygon`; нет у поселений без контура и у высот |
| `id` | объект OSM: `w` — way, `r` — relation, `n` — node, затем номер (`w91815255`) |
| `pop` | население (тег `population`), если указано |
| `ele` | высота в метрах (только у высот; `null`, если в OSM нет `ele`) |
| `adm` | `1` — муниципальная территория (`boundary=administrative`, `admin_level` 8–9) |
| `b` | `1` — контур деревни собран из участков `landuse=residential` не дальше 2 км от её точки |
| `pt` | `1` — только точка, контура нет |
| `dist` | `1` — район города, лагерь беженцев или квартал внутри города (`admin_level=10`, `place=suburb|quarter|neighbourhood`, посёлки внутри чужого муниципалитета); только в областях со снимком — сейчас Сектор Газа |
| `ruin` | `1` — разрушенный населённый пункт: крупный именованный `landuse=brownfield` или точка `historic=ruins` + `abandoned=yes` без `place` |

`counts` — число объектов каждого типа `k` (типа нет, если объектов ноль; районы с `dist` считаются отдельно в `district`), а также `approx` (с `pt`, без районов),
`builtup` (с `b`) и `ruins` (с `ruin`).

Пример объекта:

```json
{ "k": "peak", "n": "Jabal Safi", "q": "jabal safi|ג'בל סאפי", "s": "Высота", "p": [35.5445, 33.48507], "ele": 1379, "id": "n11329969264" }
```

Как собираются объекты (`scripts/osm-core.mjs`):
- поселения — `place=city|town|village|hamlet` и муниципальные границы `admin_level` 8–9; региональные советы
  (одна граница на несколько посёлков) отбрасываются — кроме муниципалитета, внутри которого стоит одноимённый
  город или посёлок (так Рафах остаётся городом, хотя внутри него Шведская деревня и Саудовский квартал);
  контур застройки внутри муниципалитета сливается с ним;
- военные — `landuse=military` и `military=*`; зоны больше 100 км² или с тремя и более поселениями внутри
  отбрасываются;
- аэродромы — `aeroway=aerodrome` и `military=airfield`;
- высоты — именованные `natural=peak|volcano`, не больше 80 самых высоких на провинцию;
- контуры упрощаются примерно до 4 м, координаты округляются до 5 знаков после запятой.

Пример запроса:

```js
const base = 'https://stezity.github.io/frontline-studio/data/';
const index = await fetch(base + 'index.json').then(r => r.json());
const region = await fetch(base + 'regions/318236.json').then(r => r.json());

// объекты провинции → GeoJSON FeatureCollection
const geojson = {
  type: 'FeatureCollection',
  features: region.features.map(f => ({
    type: 'Feature',
    id: f.id,
    geometry: f.g || { type: 'Point', coordinates: f.p },
    properties: { kind: f.k, name: f.n, subtype: f.s, population: f.pop, ele: f.ele },
  })),
};
```

## Сектор Газа

Сектор Газа и его провинции собираются по данным OpenStreetMap **на 31.12.2021**, а не по текущим.
После 2023 года редакторы OSM удаляют или переразмечают разрушенные города: Рафах стал `landuse=brownfield`,
пропали муниципальные границы Бейт-Хануна, Абасана, Хузаа. Текущие данные для такой карты непригодны.

Список задан в `OSM_SNAPSHOTS` в `scripts/osm-core.mjs` по странице
[wiki.openstreetmap.org/wiki/Gaza_Strip/Region](https://wiki.openstreetmap.org/wiki/Gaza_Strip/Region):

| id | Провинция |
|---|---|
| 1473938 | Сектор Газа |
| 4731200 | Северная Газа |
| 3935814 | Газа |
| 4731198 | Дейр-эль-Балах |
| 4731199 | Хан-Юнис |
| 4731201 | Рафах |

Дата применяется и к любой провинции, чья рамка целиком лежит в области `[34.2, 31.2, 34.58, 31.6]`.

Что получается на 31.12.2021: все 25 муниципалитетов полосы с настоящими границами (Газа, Джабалия,
Бейт-Ханун, Бейт-Лахия, Хан-Юнис, Рафах, Бани-Сухейла, Абасан, Хузаа, Эль-Карара, Нусейрат, Эль-Бурейдж,
Эль-Магази, Дейр-эль-Балах и др.), 17 районов Газы (Шуджаия, Зейтун, Рималь, Шейх-Радван, Тель-эль-Хава…)
и лагеря беженцев (Джабалия, Шати, Эль-Бурейдж, Дейр-эль-Балах, Рафах, Тель-эс-Султан…) как районы (`dist`).
Русские названия, которых нет в OSM, заданы в `OSM_SNAPSHOTS[].ru`.
Запросы к Overpass идут с `[date:"2021-12-31T00:00:00Z"]`, в файле провинции появляется поле `snapshot`,
а приложение показывает «на 31.12.2021» рядом с провинцией. Сборка в браузере использует ту же дату.

Для сборки в репозитории дату можно задать вручную в `regions.json` полем `date`: ISO-время
(`"2021-12-31T00:00:00Z"`) или `"current"` — текущие данные:

```json
{ "id": 4731201, "name": "Провинция Рафах", "date": "current" }
```

С текущими данными крупные именованные `landuse=brownfield` (или содержащие руины с тем же названием)
попадают в поселения как «Разрушенный населённый пункт» с `ruin: 1`.

## Как добавить провинцию

1. Узнайте `id` — номер relation в OSM. Проще всего в приложении: постройте фронт через **🌍 Страны**
   или добавьте провинцию в **🎯 Цели → Провинции** и нажмите **📋 Скопировать ID для regions.json**.
2. Добавьте строку `{ "id": …, "name": "…" }` в `regions.json` и запушьте в `main`.
3. GitHub Action **«Обновить данные OSM»** (`.github/workflows/update-data.yml`) пересоберёт данные и
   закоммитит изменения в `data/`. Он запускается:
   - при пуше в `main`, если изменились `regions.json`, `scripts/build-data.mjs` или `scripts/osm-core.mjs`;
   - раз в неделю — в понедельник в 03:00 UTC, чтобы подтянуть правки в OSM;
   - вручную: **Actions → «Обновить данные OSM» → Run workflow** (`workflow_dispatch`).

Провинцию, которой нет в `regions.json`, приложение всё равно соберёт в браузере — `regions.json` нужен,
чтобы данные открывались сразу и у всех.

Защита от плохих ответов Overpass:
- пустой ответ по объектам при более чем 20 точках поселений считается сбоем зеркала — провинция не
  перезаписывается;
- **проверка на падение**: если военных объектов, аэродромов или контуров поселений было не меньше 5,
  а стало меньше половины, сборка провинции завершается ошибкой «подозрительное падение», прежний файл
  остаётся (проверка не действует, когда меняется дата снимка);
- если данные не изменились, у файла сохраняется прежнее время `updated`, и еженедельный запуск ничего
  не коммитит;
- ошибка одной провинции не останавливает сборку остальных; успешно собранные провинции Action всё равно
  коммитит, а сам запуск помечается ошибкой.

Провинция, удалённая из `regions.json`, пропадает из `index.json`; её файл в `data/regions/` не удаляется.

Локальная сборка (Node.js; в Action используется Node 22):

```
npm ci
node scripts/build-data.mjs                  # все провинции из regions.json
node scripts/build-data.mjs 318236 318309    # только указанные
```

`npm run build-data` — то же, что первая команда. Скрипт обращается к Overpass API (overpass-api.de и
зеркала) с повторами при занятости серверов.

## Устройство репозитория

```
index.html                     приложение целиком: HTML, CSS и JS в одном файле (osm-core встроен)
regions.json                   провинции, для которых собираются данные
data/index.json                список собранных провинций
data/regions/<id>.json         объекты одной провинции
scripts/build-data.mjs         сборка data/ из OpenStreetMap (Node)
scripts/osm-core.mjs           общая обработка данных OSM — для скрипта и для сборки в браузере
.github/workflows/update-data.yml   Action «Обновить данные OSM»
package.json                   зависимость @turf/turf и команда build-data
```

Внешние библиотеки приложение подключает с CDN: Leaflet, MapLibre GL, maplibre-gl-leaflet, Turf,
polygon-clipping.
